# cfg4ai 优化计划（功能 + 界面 双线打磨）

> 版本：v1.0（2026-08-20）｜ 性质：基于三份调研的详细优化蓝图
> 调研依据：`docs/research/capability-management-research.md`（功能体系）｜ `docs/DESKTOP-UI-DESIGN.md`（设计系统）｜ Gio 技术矩阵调研
> 定位：回应"功能只有粗浅导入导出、页面 low 爆了"两点批评，给出可施工的完整方案

---

## 0. 问题诊断（诚实基线）

### 功能面：只有管道，没有管理

当前 cfg4ai 是采集→导出/迁移的单向管道。对照一流配置管理工具的能力全集（10 维度 43 功能点），缺失 31 个，其中 8 个是硬伤：看不见内容、改不了、建删无门、没有开关、冲突盲飞、无条目级后悔药、secret 无界面、搜索缺失。

### 设计面：裸奔的默认样式

默认白底 + 默认蓝、纯文字按钮当导航、13 个 RadioButton 竖排当工具选择、无图标/动画/暗色主题/卡片层次/空态/toast/模态/命令面板。另有真实 bug：goroutine 操作完成后不重绘（缺 `w.Invalidate()`）。

## 3. 设计篇：界面设计系统

> 完整施工版见 `docs/DESKTOP-UI-DESIGN.md`（584 行，含全部数值与 M1–M5 迁移步骤）。此处为纲领。

### 3.1 设计语言

- 双主题：深色默认（Linear 式：底 #0B0C0E、卡片 #171A21、accent 靛蓝 #5E6AD2），浅色用 Primer 全套原值；跟随系统 + 手动切换
- 字体：9 级层级（H1 28sp Bold → Caption 12sp）；embed Noto Sans SC 子集兜底中文（防麒麟精简系统豆腐块）
- 间距 12 档、圆角 5 档、阴影 E1–E4（Gio 无 box-shadow 用多层叠画实现）

### 3.2 布局骨架

侧栏 232dp（窄窗折 56dp 图标栏）+ 内容区（Header 52dp + max-w 960dp）+ 状态栏 28dp。

### 3.3 关键组件改造

| 现状 | 改造后 |
|------|--------|
| 纯文字按钮当导航 | component.NewNav 图标导航（选中动画/hover） |
| 13 个 RadioButton 竖排 | chip 流式布局（outlay.FlowWrap）或 Quick Pick 过滤下拉 |
| 顶部一行文字消息 | Toast（右下栈+倒计时条+图标） |
| 无确认直接恢复 | 危险操作 Modal 二次确认 |
| 无 | ⌘K 命令面板（全局搜索+跳转+动作） |
| 硬切页 | 切换淡入上移 180ms（尊重 ReducedMotion） |
| 白底裸奔 | 卡片 Surface（圆角+阴影+hover）+ 语义色层级 |
| 无图标 | Material 图标集 |

### 3.4 Gio 技术路径（调研已验证可行）

导航/AppBar/模态/菜单/tooltip/分栏/网格直接用 gioui.org/x/component；卡片阴影/补间/toast/命令面板用约 300 行自绘骨架（调研已给核心代码）；先修 goroutine 不重绘 bug（操作完成需 w.Invalidate()）。Gio 做不到的三件（毛玻璃/系统全局热键/托盘）属可接受妥协。

## 5. 验收标准

### 功能线
P0 八项：桌面应用内完成"浏览内容→搜索定位→编辑→新建/删除→启停→冲突处置→历史回滚→secret 管理"全闭环，全程不碰文件系统与命令行。每功能有 e2e 验收用例。

### 设计线
双主题切换正确；导航图标化；卡片/Toast/Modal/命令面板就位；页面过渡动画；空态与首次引导；中文不豆腐块。对照 DESKTOP-UI-DESIGN.md §6.3 逐条验收。
